# 优化师策略库

> **本文档是什么:** 跨在跑广告的**宏观投放策略指导** — 节奏 / 阶段目标 / 效果方向 / 数据洞察总结。**初始化包内为空骨架**,接入实例后由用户按月追加经验沉淀。
> **本文档不是什么:** 不写"本次创建用什么参数"(那属于 `project/instances/{instance}/groups/{group}/group.yaml.strategy`);不写 Meta API 物理硬约束(那属于 [Meta广告执行QA.md](../../Meta广告执行QA.md) 的 13 条 safety rails);不写"如何 introspect 习得"(那属于 [meta-ads-sheet-mapping/references/](../skills/meta-ads-sheet-mapping/references/));不写 group 内反直觉点(那属于 `groups/{group}/notes/`)。
> **关联指向:** 业务能力路由见 [capability-routing.md](../capability-routing.md);本文档原则:抽方法论不抽答案,具体业务结论按月归档。

---

## 一、写什么(What goes here)

| ✅ 应写 | ❌ 不应写 |
|---|---|
| 跨多个 campaign 的**节奏与阶段规划**(Phase 1 Launch → Phase 2 Hotsale → ...) | 单次创建用 CBO 还是 ABO(去 group.yaml.strategy.budget) |
| 不同**市场 / 国家**之间的差异总结(对比表) | 某个 instance 的 identity 字段(去 instance.yaml) |
| 数据回收后的**效果优化方向**(哪类素材表现好、哪类受众转化高) | tier 列表 / saved_audience_id(去 group.yaml.strategy.audiences) |
| 阶段性**KPI 设定**与达成情况复盘 | 命名 segment 顺序(去 group.yaml.strategy.naming_pattern) |
| 上线后才暴露的**经验法则**(如"周三发新素材转化率高于周一") | Meta API 物理约束(去 Meta广告执行QA.md) |

> 决策口诀:**这条信息是"决定 sheet/创建当次怎么传"还是"事后怎么调"?** 前者去 group.yaml,后者才来这里。
> 历史教训:曾把"Lifetime+CBO 是默认"写进本文 → 错!那是创建参数,该写 group.yaml.strategy。**决策口诀:决定 sheet/创建当次怎么传 → group.yaml;事后怎么调 → 本文档。**

## 二、更新方式

- **被动响应** — 用户发起询问(如"上个月效果如何"、"节奏需要调整吗")时,agent 应基于本文与最近 snapshots 提供回答。
- **按月归档** — 每月一份小节(YYYY 年 M 月),复制下方"模板"段填入本月内容。月内迭代采用 patch / merge 方式,不重写整月。
- **写入门槛** — 同一条经验在 ≥ 2 个 instance 都验证过 → 提升为本文跨项目法则;只在 1 个 instance 出现 → 留在 `instances/{instance}/notes/`,不要急着提升。

## 三、本文骨架(每月条目按此填)

```
## YYYY 年 M 月

### 广告创建策略
- (本月新增/调整的跨 campaign 创建方向 — 不写单次参数)

### 投放阶段规划
- (本月所处的 phase + 节奏变化)

### 投放目标设定
- (KPI 与目标群体)

### 跨市场差异
- (如有多 instance 在跑,做对比表)

### 效果优化
- (数据回收后的洞察与下月调整方向)
```

## 四、模板（下月复制使用）

### YYYY 年 M 月

#### 广告创建策略

- *(待填:本月跨 campaign 的创建方向、阶段定位、素材类型偏好等。注意:具体投放参数留给 group.yaml.strategy,本节只写跨 campaign 的趋势与方向)*

#### 投放阶段规划

- *(待填:Phase 划分、各 phase 起止时间、阶段重点)*

#### 投放目标设定

- *(待填:KPI 列表、目标受众定位、与品牌方对齐的核心指标)*

#### 跨市场差异

- *(待填:如有 ≥ 2 个 instance 在跑,对比维度可包括投放模式、预算结构、Tier 数、Objective 偏好、受众年龄区间等)*

#### 效果优化

- *(待填:首批数据回收后的洞察、表现好/差的素材-受众组合、下月调整方向)*

## 五、写作纪律(后续接入的 agent 必读)

1. **不写绝对数值,写相对趋势** — "视频转化率高于图文 40%" 比 "视频转化率 6.8%" 更有跨项目复用价值
2. **不预设具体答案** — 即使仅接入了一个项目,也使用 "品牌 X" / "市场 Y" 等占位符,不写真实品牌名
3. **每条经验标注出处** — 如 "(根据 YYYY-MM 第 W 周数据回收)",便于后续判断时效性
4. **过期经验需迁出或标注** — 投放节奏变化时,旧月份的阶段性经验可能失效,过期内容迁移至 `instances/{instance}/notes/archive/`
5. **不写 customer-project-id / account-id / 邮箱 / open_id 等具体值** — 此为初始化包的硬性边界
